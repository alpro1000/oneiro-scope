# Как попасть в каталоги: MCP Registry, Claude, ChatGPT

> Почему это отдельный документ. Обзор конкурентов дал один вывод сильнее
> остальных: **связывающее ограничение сейчас — не количество инструментов, а
> то, что сервер невозможно найти.** У VedAstro 604★ и 6 инструментов, у нас 19
> и шесть интерактивных видов — и это не имеет значения, пока нас нет ни в
> одном списке. Сервер лучше, но невидимый, проигрывает худшему в каталоге.

---

## 0. Что нужно сделать ДО любой подачи

Это не бюрократия — на этих трёх пунктах заявку либо развернут, либо примут
и потом снимут.

### 0.1 Лицензия Swiss Ephemeris — блокирующий пункт

Astrodienst распространяет Swiss Ephemeris по **двойной лицензии**: AGPL
либо коммерческая Professional License. Выбор нужно сделать **до публичного
запуска сервиса**, а не после.

- **AGPL** — бесплатно, но обязывает открыть исходники **всего сервиса**,
  который использует библиотеку по сети. Для нас это весь backend.
- **Professional** — платно (первая лицензия порядка CHF 750 по документации
  Astrodienst; сверить актуальную цену на astro.com/swisseph), backend
  остаётся закрытым.

Пока это не решено, подавать в каталоги не надо: в форме Claude и в MCP
Registry есть поле лицензии, и неверный ответ там хуже, чем отсутствие
заявки. **Решение владельца, не моё** — я не могу ни купить лицензию, ни
подписать её.

### 0.2 Свободный первый вызов

У всех, с кем нас будут сравнивать, время до первого успешного вызова близко
к нулю: VedAstro — 5 запросов/мин анонимно, AstrologyAPI — 100 бесплатных
вызовов сразу, aryaminus/astro — вообще без авторизации. У нас OAuth
обязателен, то есть первый вызов невозможен без регистрации.

Это ровно та метрика, по которой каталоги и обзорщики判 судят о сервере.
Варианты обсуждаются отдельно (анонимный лимит / demo-токен со страницы
`/connect`); здесь это записано как то, что стоит закрыть до подачи, а не
после.

### 0.3 Прод должен отвечать

Каталог проверяет `remotes[].url` живым запросом. Перед подачей:

```
<backend>/health                → 200
<backend>/connect/diagnostics   → ready: true, все строки ok
<backend>/.well-known/oauth-protected-resource  → RFC 9728 документ
```

`/connect/diagnostics` теперь включает строку `browser_origins` — та самая
CORS-проверка, из-за которой фронт не мог достучаться до бэка.

## 1. MCP Registry (официальный)

Манифест уже лежит в корне репозитория: **`server.json`**.

Пространство имён выбрано `io.github.alpro1000/oneiroscope` намеренно —
GitHub-аутентификация не требует DNS-записей и работает через device flow,
то есть подача занимает минуты, а не сутки ожидания распространения DNS.
(Свой домен тоже возможен — через TXT-запись; смысл имеет, когда появится
`oneiroscope.com`.)

```bash
# 1. Поставить публикатор (см. релизы modelcontextprotocol/registry)
#    Ставить руками, версию сверить на месте.

# 2. Проверить манифест против живой схемы. Схема датирована (2025-12-11) и
#    может быть новее — `init` сгенерирует актуальный скелет для сверки:
mcp-publisher init            # в пустой папке, НЕ в корне репозитория —
                              # иначе перезапишет наш server.json

# 3. Войти под владельцем репозитория alpro1000/oneiro-scope
mcp-publisher login github

# 4. Опубликовать
mcp-publisher publish
```

**Это делает владелец.** Публикация в открытый реестр — необратимое внешнее
действие: запись становится видна всем и попадает в зеркала каталогов.

Что проверить в `server.json` перед подачей:

- `version` — поднимать при каждой повторной публикации;
- `remotes[].url` — совпадает с `MCP_PUBLIC_URL` на Render;
- `description` — первые ~200 символов идут в карточку. Сейчас там
  сознательно вынесено то, чего нет у конкурентов (цитата-улика на каждый
  счёт, лестница уверенности, интерактивные виды), а не «ещё один
  астрологический API».

## 2. Каталог коннекторов Claude

> Тексты заявки, ответы на вопросы формы и честный список рисков —
> в **`submission-pack.md`** рядом с этим файлом. Здесь — только процесс.

Подача через форму Anthropic для directory-листинга (ссылка — в актуальной
документации по коннекторам; она менялась, поэтому не вбиваю её сюда
намертво).

Что спросят и что у нас есть:

| Пункт | Состояние |
| --- | --- |
| Публичный HTTPS MCP-эндпоинт | ✅ `<backend>/mcp` |
| OAuth 2.1 + RFC 9728 discovery | ✅ `MCP_AUTH_ISSUER`, `/.well-known/…` |
| Privacy policy | ✅ `/legal/privacy` |
| Terms of service | ✅ `/legal/terms` |
| Что делает с данными пользователя | ✅ описано в privacy; сны хранятся только при `remember=true` |
| Лицензия | ⛔ см. §0.1 |
| Бесплатный пробный доступ | ⛔ см. §0.2 |

Отдельно стоит указать **MCP Apps**: по обзору рынка ни один астрологический
или сновидческий сервер не отдаёт `ui://`-ресурсы. Для каталога это
различитель, который видно сразу.

## 3. ChatGPT

Два разных механизма, их часто путают:

- **Connectors / Deep Research** — добавляется по URL, как в Claude. Требует
  того же: публичный эндпоинт, OAuth, политики.
- **Apps SDK** — каталог приложений внутри ChatGPT, отдельная подача и
  отдельные требования к UI. Наши виды написаны на `io.modelcontextprotocol/ui`,
  что для Apps SDK родная модель, но заявка отдельная.

Начинать стоит с коннектора: та же готовность, что и для Claude.

## 5. Чем заполнять карточку

Не «AI-астрология» — это дешёвая категория, забитая доверху. Из обзора
конкурентов честная формулировка одна:

> **Единственный сервер, который показывает свою работу.**
> Детерминированный расчёт, у каждого утверждения — источник и уверенность,
> кодировка сна с цитатой фразы под каждым счётом, и интерактивные виды,
> где любая строка отдаёт свои точные числа обратно в разговор.

Чего **не** писать: «Swiss Ephemeris» как отличие. Им пользуются VedAstro,
W8s, intellecat, AskSoma, Kerykeion и почти наверняка AstrologyAPI, а
Astrodienst его написал. Это гигиена, а не преимущество, и человек,
знающий рынок, прочитает такую заявку как незнание рынка.
