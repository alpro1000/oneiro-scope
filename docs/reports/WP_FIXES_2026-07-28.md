## WP-6 — Блок версионирования в каждом ответе ✅

**Что изменилось.** Новый модуль `backend/mcp/tools/_meta.py`: обёртка
`with_meta` (sync и async), которая добавляет в каждый ответ инструмента блок

```json
"meta": {
  "server_version": "1.5.0", "commit": "<git sha|RENDER_GIT_COMMIT|untracked>",
  "schema_version": "2", "request_id": "req_…", "input_hash": "sha256:…",
  "duration_ms": 12, "cache_hit": false, "computed_at": "…+00:00"
}
```

Все регистрации в `backend/mcp/server.py` переведены на
`mcp.tool()(with_meta(fn))` — обойти обёртку нельзя без правки server.py.
`input_hash` считается от связанных (bound) аргументов вызова — одинаковый
вход даёт одинаковый хэш, разный — разный. `computed_at` всегда tz-aware.

**Тесты.** `backend/tests/test_response_meta.py`:
- AST-проверка: каждая регистрация обёрнута `with_meta` (структурный страж);
- runtime: sync- и async-инструменты реально возвращают все 8 полей;
- стабильность `input_hash` (два одинаковых вызова → одинаковый хэш,
  другой вход → другой хэш; `request_id` при этом различается);
- tz-awareness таймстампов ответа dreams.

**Критерии приёмки.** Выполнены: блок присутствует во всех ответах (47/47
инструментов через одну точку), commit берётся из RENDER_GIT_COMMIT/git.
`cache_hit` пока константно `false` — честно: серверного кэша ответов на
MCP-пути сейчас нет; поле станет информативным, если кэш появится.

## WP-1 — Полные эфемериды: SWIEPH без Moshier-фолбэка ✅

**Что изменилось.**

1. **Файлы в репо**: `backend/data/ephemeris/` — `sepl_18.se1` (473 KB),
   `semo_18.se1` (1.27 MB), `seas_18.se1` (218 KB) с
   raw.githubusercontent.com/aloistr/swisseph (официальное зеркало данных
   Astrodienst; сжатый JPL DE431, диапазон 1800–2400 AD; Хирон — в seas).
2. **Единая точка конфигурации**: новый `backend/core/ephemeris.py` —
   resolve каталога (env-переопределение → путь в репо), проверка всех трёх
   файлов **при импорте** с `RuntimeError` при отсутствии, один вызов
   `swe.set_ephe_path`, экспорт `FLAGS = FLG_SWIEPH|FLG_SPEED`, версии
   swisseph, хэшей файлов, строк provenance. Отсутствие файлов = падение на
   старте (FastAPI и MCP-сервер импортируют модуль на старте и логируют
   сводку), а не тихий даунгрейд.
3. **Все 9 расчётных модулей** переведены с `FLG_MOSEPH` на импорт флагов из
   core: `astrology/{ephemeris,synastry,transits_engine,transit_arcs,report,
   solar_return,astrocartography}`, `strategic/pattern_engine`,
   `lunar/engine`, плюс `engine/ephemeris_engine` (dual-mode ветка удалена).
4. **Фолбэк-лестницы удалены**: кеплеровские аппроксимации
   (`_calculate_fallback`), MOSEPH-retry при исключении, stub-era проверки
   `jd < 2_000_000`, `_fallback_julday`/`_fallback_longitude` в lunar.
   Дополнительный страж: `calculate_planet_position` проверяет **возвращённые**
   флаги `calc_ut` — если C-библиотека тихо подменила источник (битый файл
   одного тела), это RuntimeError, а не «почти SWIEPH».
5. **Provenance отражает фактический источник**: `Swiss Ephemeris 2.10.03
   (SWIEPH)` / `… / JPL DE431 .se1 files (SWIEPH)` из `swe.version`; убраны
   слова Moshier/MOSEPH из строк методологии в MCP-инструментах, API,
   /health, README. `/health` теперь отдаёт фактический путь, файлы и версию.
   Lunar-provenance несёт sha256 всех трёх файлов + версию swisseph.
6. Хирон: раньше под MOSEPH тихо падал в кеплеровскую заглушку с мусорной
   долготой (в `mean_motions` его вообще не было). Теперь считается из
   seas_18.se1 — покрыт тестом (долгота валидна, расстояние > 5 а.е.).
