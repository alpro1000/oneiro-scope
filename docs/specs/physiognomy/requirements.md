# Physiognomy Reading — Requirements

> **English TL;DR:** Face-reading module (Chinese mianxiang + Western
> physiognomy traditions) as a reflective/entertainment service.
> Deterministic-first: facial metrics are computed from landmarks
> (geometry, confidence 1.0), interpretations come from a cited
> tradition dictionary (confidence 0.6 — BELOW the symbol-dictionary
> tier because physiognomy has no scientific validity). Photo never
> needs to leave the client: the browser extracts landmarks locally.

## Контекст

Пользователь загружает своё фото (или отвечает на анкету о чертах
лица) и получает рефлексивное чтение по традициям:

- **Мянсян (面相)** — пять элементов, три двора (三停), двенадцать
  дворцов (十二宮), словарь черт.
- **Западные школы** — три этажа Лафатера, дилатация/ретракция
  Кормана, конституции Кречмера/Шелдона, современный fWHR (как
  спорный научный след).

## Научный статус (обязательная рамка)

Современные исследования (Todorov «Face Value» 2017; мета-анализ
Geniole et al. 2015 по fWHR) показывают: устойчивые черты личности по
лицу не читаются; слабый сигнал есть только у fWHR и тот оспаривается.
Поэтому:

- КОГДА система выдаёт любую трактовку, она ДОЛЖНА нести
  `confidence = 0.6` (tradition tier, ниже symbol-dictionary 0.8) и
  `source` с названием традиции/трактата.
- КОГДА формируется ответ, система ДОЛЖНА включать дисклеймер:
  рефлексивно-развлекательный характер; физиогномика научно не
  валидирована; запрещено использовать для оценки других людей,
  найма, кредитных и правовых решений.
- Система НЕ ДОЛЖНА выдавать суждения о здоровье, диагнозы,
  привлекательности, этнической принадлежности.

## Функциональные критерии (EARS)

1. КОГДА клиент передаёт 468 лендмарок MediaPipe FaceMesh (или
   именованные точки), система ДОЛЖНА детерминированно вычислить
   метрики лица (fWHR, пропорции третей, отношение ширины к высоте,
   межглазье, отношение челюсть/скулы) и вернуть их в ответе с
   provenance «landmark geometry» (confidence 1.0).
2. КОГДА метрики вычислены, система ДОЛЖНА классифицировать тип по
   пяти элементам (первичный + вторичный со score) и доминирующий
   двор (верх/середина/низ) по документированным порогам.
3. КОГДА клиент не может дать фото/лендмарки, система ДОЛЖНА принять
   анкету перечислимых черт (форма лица, посадка глаз, веко, губы,
   челюсть…) и выдать чтение только по словарю черт.
4. КОГДА доступна и геометрия, и анкета, геометрия имеет приоритет
   для измеримых черт; анкета дополняет неизмеримые (веко, взгляд).
5. КОГДА запрошен `GET /methods`, система ДОЛЖНА вернуть список
   поддерживаемых систем с первоисточниками и научным статусом.
6. КОГДА загружено фото на серверный эндпоинт и на сервере нет
   CV-зависимостей, система ДОЛЖНА вернуть структурированную ошибку
   501 с указанием клиентского пути (браузерные лендмарки) и
   анкетного fallback — а не 500.
7. Ответ ДОЛЖЕН быть двуязычным (ru/en) по параметру locale.

## Приватность

- Основной путь: фото НЕ покидает устройство — лендмарки извлекаются
  в браузере (MediaPipe Tasks JS), на сервер уходят только координаты.
- Серверный photo-эндпоинт — опция для окружений с установленным
  mediapipe; файл обрабатывается в памяти и не сохраняется.
- Система предназначена ТОЛЬКО для само-рефлексии владельца фото.

## Acceptance (домен-стиль)

- Метрики для синтетического набора лендмарок совпадают с ручным
  расчётом в пределах допуска 1e-6.
- Каждая трактовка несёт source из KB и confidence 0.6.
- Ответ содержит дисклеймер и не содержит запрещённой
  детерминистской лексики («будет», «точно», «означает что вы»).
